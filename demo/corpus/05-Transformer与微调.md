# 面试八股 · Transformer 与微调

> 自写的演示语料：题目与答案是通用技术知识，不是任何机构的材料。

### 26. 自注意力是怎么算的，为什么要除以根号 d

输入序列的每个 token 先投影成三组向量：查询 Q、键 K、值 V。
注意力权重是 `softmax(QKᵀ / √d_k) V` —— 先用 Q 与所有 K 做点积得到相关性分数，
除以 `√d_k` 后过 softmax 归一化，再对 V 加权求和。

除以 `√d_k` 的原因是**数值稳定性**：点积是 d_k 个乘积之和，d_k 越大方差越大，
分数落进 softmax 的饱和区后梯度会趋近于 0（训练不动）。除以维度的平方根把方差拉回 1 附近，
这是"缩放点积注意力"里"缩放"两个字的全部含义。

### 27. 多头注意力相比单头的优势是什么

单头只能学一种"关注方式"。多头把 Q/K/V 拆成 h 份，每份在更低的维度上独立做注意力，
最后拼接再投影 —— 相当于让模型在**不同的表示子空间**里并行捕捉不同关系：
有的头盯语法依赖（主谓一致）、有的头盯指代（代词指向谁）、有的头盯位置邻近。

代价主要是实现复杂度，参数量与单头基本持平（拆维度不增参数）。
工程上要注意的是 **KV 头数**：推理时 KV 缓存的大小与头数成正比，
所以 LLaMA 这类模型用 GQA（分组查询注意力）让多个 Q 头共享一组 KV，把缓存压下来。

### 28. 位置编码为什么必要，RoPE 好在哪

自注意力本身是**置换等价的**：把输入序列打乱，注意力输出只会跟着打乱，
分数一点不变 —— 也就是说它压根不知道谁在前谁在后。所以必须额外注入位置信息。

早期做法是正弦位置编码（加在输入上），RoPE 换成**旋转**：把 Q/K 向量按位置角旋转，
两个向量点积的结果只依赖它们的**相对距离**。好处有三个：相对位置天然被建模、
可以外推到训练时没见过的更长序列、不增加参数。这也是现在主流大模型基本都用 RoPE 的原因。

### 29. LoRA 微调的原理和常用参数

LoRA 冻结原权重 `W`，在旁边学一个低秩增量 `ΔW = BA`（`B` 是 d×r、`A` 是 r×k，r 远小于 d、k），
前向变成 `Wx + BAx`。可训练参数从 d×k 降到 r×(d+k)，7B 模型上通常只训练 0.1%～1% 的参数。

三个关键超参：`r`（秩，常用 8/16/32，任务越难越大）、`lora_alpha`（缩放，常按 2r 设）、
`target_modules`（一般挂到所有线性层 `q/k/v/o/gate/up/down`，只挂 q、v 会明显欠拟合）。
训练完可以用 `merge_and_unload()` 把增量合并回原权重，推理时**零额外延迟** ——
这也是 LoRA 比 adapter 类方法更受欢迎的原因。

### 30. 量化为什么能省显存，代价是什么

显存占用的大头是权重与 KV 缓存，把 FP16（2 字节）换成 INT8/INT4（1/0.5 字节）
理论上直接省一半到四分之三。做法是给每组权重存一个缩放因子（scale）与零点（zero point），
`w ≈ scale × (q − zero)`，反量化后参与计算。

代价有三块：① **精度损失**，权重被离散化后小模型的输出分布会漂移，
所以有了 SmoothQuant、GPTQ、AWQ 这些"按权重重要性分配精度"的方法；
② **反量化开销**，如果算子不支持低精度计算，就要在计算前转回 FP16，速度可能反而变慢；
③ **量化不是无损压缩**，同一份权重用不同校准集量化，效果会差 —— 所以要用真实业务样本校准。

### 31. 微调、RAG、提示词工程该怎么选

按"知识在哪、要不要改行为"来分：**知识更新频繁且要可溯源** → RAG（改库即生效，答案能给引用）；
**要固定输出风格/格式、学领域术语** → 微调（LoRA 就够，别上全参）；
**只是让模型按格式回答、任务简单** → 提示词工程（零成本、当天上线）。

三者不互斥，常见组合是"微调一个小模型学格式 + RAG 提供事实"。
判断顺序建议：先用提示词 + RAG 把基线跑出来、量出错误分布，
只有当错误集中在"风格/格式/术语"而不是"缺知识"时，才值得付出微调的工程成本。
